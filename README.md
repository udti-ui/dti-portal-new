# بوابة الطالب - UDTI

واجهة ويب احترافية للطالب والإدارة مبنية بـ Next.js و Tailwind CSS، قابلة للنشر على Vercel.

## المميزات

- تسجيل دخول الطالب
- عرض العلامات الدراسية
- المعدل الفصلي والتراكمي
- سجل الإنذارات
- الحالة الدراسية
- جدول الدوام الأسبوعي
- إنشاء رمز الطالب (QR / Barcode mock)
- إنشاء حسابات الطلاب من لوحة التحكم لمشرفي الدرجة الأولى
- إدارة المشرف
- نظام الحضور والغياب
- دردشة الطلاب مع الإشراف على المحتوى والحظر والحذف التلقائي للرسائل بعد 48 ساعة
- بوابة المدرسين لقائمة الطلاب وسجل الحضور والتنبيهات
- تبويب تواصل الطالب مع المدرس بسجل استفسارات ومرفقات وردود محفوظة
- تبويب إعلانات الطالب، مع تمييز الإعلانات غير المقروءة، وإدارة النشر حسب السنة والمادة

## دردشة الطلاب

1. اضبط `SUPABASE_SERVICE_ROLE_KEY` في بيئة الخادم، ثم شغّل `supabase-student-chat.sql` من محرر SQL في Supabase. ينشئ الملف جداول الدردشة ويجدول حذف الرسائل الأقدم من 48 ساعة كل دقيقة عبر `pg_cron`.
2. إدارة فتح الدردشة وإغلاقها والحظر الدائم متاحة لمشرفي الدرجة الأولى. ويمكن لمشرف الدرجة الأولى منح حساب طالب قائم صلاحية قسم دعم الدردشة أو سحبها. يستطيع الموظف دخول لوحة التحكم بحسابه كصلاحيات الدرجة الرابعة، كما يدخل إلى حساب الطالب المعتاد؛ تظهر الدردشة في تبويب الطالب نفسه مع اختيار السنة الأولى أو الثانية وإرسال الرسائل من الحساب نفسه.
3. يتضمن ملف SQL جدول موظفي الدعم وحقول انتهاء الكتم وسببه. شغّل الملف بعد التحديث قبل استخدام الميزات الجديدة. تبقى قيود الحظر القديمة دائمة ما لم يُلغها المشرف.
4. يستطيع الطالب إرسال الصور وملفات PDF أو TXT حتى 1 ميغابايت؛ تُضغط الصور الكبيرة تلقائيًا، كما يمكن تعديل الرسائل النصية أو حذفها. ترتبط بيانات المرفقات وإيصالات المشاهدة برسائلها في قاعدة البيانات، فتحذف معها تلقائيًا عند انتهاء مدة 48 ساعة.
5. يستطيع موظف الدعم عند الضغط على اسم الطالب رؤية رقمه الجامعي ورقم الموبايل وصورته الشخصية، وكتم الطالب 24 ساعة مع تسجيل السبب. تظهر رسائل الدعم بشارة واسم أحمر وإطار ذهبي. يتحقق الخادم من صلاحية الدعم ويسجل منحها وسحبها ودخول الدردشة ومشاهدة الملفات الشخصية والكتم في سجل النظام.

## تفعيل بوابة المدرسين

1. تأكد من إعداد `SUPABASE_SERVICE_ROLE_KEY` في بيئة الخادم؛ لا تضعه في متغيرات `NEXT_PUBLIC_*`.
2. شغّل `supabase-teacher-portal.sql` من محرر SQL في Supabase.
3. سجّل الدخول إلى لوحة التحكم بحساب مشرف الدرجة الأولى، ثم افتح **حسابات المدرسين** لإنشاء حساب يتضمن الاسم الكامل واسم المستخدم وكلمة المرور، أو اختر مدرسًا موجودًا لتعديل بياناته.
4. افتح **إدارة المدرسين والمواد** لإسناد المواد لكل مدرس وتحديد السنة الدراسية.
5. يفتح المدرس `/teacher` أو يختار **دخول المدرسين** من صفحة لوحة التحكم. تعرض الصفحة بيانات طلاب السنة المرتبطة بالمادة وسجل الحضور والتنبيهات للمادة المسندة فقط، مع بحث وتصفية بالفئة وتنزيل القائمة المعروضة كملف CSV متوافق مع Excel.
6. بعد إعداد المواد عبر `supabase-academic-management.sql`، شغّل `supabase-teacher-grades.sql` من محرر SQL في Supabase. من تبويب **العلامات** يختار المدرس بشكل مستقل مكونات كل مادة (البطاقة، النشاط، المذاكرة النظرية والعملية، والامتحان النظري والعملي) ويحدد سقف كل مكون مفعّل. ثم يدخل العلامات منفردة أو يختار عدة مكونات لقائمة Excel واحدة تحمل اسم المادة والتاريخ والتسلسل. تتم مطابقة العلامات عند إعادة الرفع بالرقم الجامعي، ويُعرض تنبيه لكل مكون بأسماء الطلاب ذوي الخانات الفارغة أو العلامات المتجاوزة للسقف دون إيقاف استيراد بقية العلامات. تظهر للطالب المواد التي لها علامات فقط، وتُعرض كل علامة مع سقفها دون جمع تلقائي.

## التحكم بتغيير الرقم الجامعي

شغّل `supabase-student-id-change.sql` من محرر SQL في Supabase واضبط `SUPABASE_SERVICE_ROLE_KEY` في بيئة الخادم. يستطيع مشرف الدرجة الأولى من تبويب **الطلاب** فتح أو إغلاق تغيير الرقم الجامعي للسنة الأولى والثانية كلٌ على حدة. عند الإغلاق، يمنع الخادم طلب التغيير حتى لو حاول الطالب تجاوز الواجهة؛ تبقى السنة مفتوحة افتراضيًا إلى أن يغيّر المشرف إعدادها.

## الإعلانات وإشعارات تيليجرام

1. شغّل `supabase-announcements.sql` من محرر SQL في Supabase بعد إعداد المواد عبر `supabase-academic-management.sql`.
2. أضف `TELEGRAM_BOT_TOKEN` كمتغير بيئة سري على الخادم أو منصة الاستضافة، ثم أعد تشغيل/نشر التطبيق. لا تضع رمز البوت في ملفات المشروع أو في متغير `NEXT_PUBLIC_*`.
3. يستطيع مشرف الدرجة الأولى نشر إعلان للإدارة واختيار السنة الأولى أو الثانية أو كل السنوات. ويستطيع المدرس النشر من الصفحة ضمن المواد المسندة إليه فقط.
4. يظهر الإعلان لطلاب الفئة المستهدفة، ويظهر غير المقروء أولًا بخلفية صفراء. تتحدث القائمة تلقائيًا كل دقيقة، ويحتاج الطالب إلى تحديد الإعلان كمقروء لإزالته من قائمة غير المقروء.
5. يمكن إرفاق صورة أو PDF أو Word أو TXT بحد أقصى 5 ميغابايت، مع معاينة الإعلان والمرفق قبل النشر. تحفظ الملفات في مخزن خاص ولا تظهر روابطها إلا بعد التحقق من الطالب.
6. يرسل النظام إشعار تيليجرام فور النشر إلى الطلاب الذين ربطوا حساباتهم بالبوت وفعّلوا إشعارات تيليجرام، ضمن السنة المختارة أو جميع السنوات بحسب استهداف الإعلان. يجب أن يكون الطالب قد بدأ محادثة مع البوت؛ لا يستطيع تيليجرام إرسال رسالة خاصة لحساب لم يبدأ المحادثة.
7. يستطيع مشرف الدرجة الأولى حذف أي إعلان، ويستطيع المدرس حذف الإعلانات التي نشرها من حسابه.
8. إذا سبق مشاركة رمز البوت في محادثة أو مكان غير موثوق، ألغِه وأنشئ رمزًا جديدًا عبر BotFather قبل تعيينه في إعدادات الاستضافة.

## استفسارات الطلاب للمدرسين

1. شغّل `supabase-teacher-inquiries.sql` من محرر SQL في Supabase بعد إعداد `supabase-teacher-portal.sql` و`supabase-academic-management.sql`.
2. يختار الطالب **تواصل مع المدرس**، ثم السنة الدراسية وبعدها المادة، ويكتب سؤاله ويرفق صورة أو PDF أو Word أو TXT حتى 5 ميغابايت. تُحفظ الاستفسارات والردود في سجل دائم، وتُتاح المرفقات عبر روابط مؤقتة بعد التحقق من الحساب.
3. تظهر الاستفسارات في تبويب **استفسارات الطلاب** لدى المدرسين المعيّنين للمادة فقط. يصل إشعار تيليجرام للمدرس عند وجود Chat ID مربوط، ويصل للطالب إشعار بالرد إذا ربط حسابه وفعّل تنبيهات تيليجرام.

## المقررات والمحاضرات

1. بعد تشغيل `supabase-academic-management.sql`، شغّل `supabase-announcements.sql` لتجهيز جدول المحاضرات ومخزن الملفات الخاص.
2. يختار الطالب تبويب **المقررات** ثم السنة والمادة، ويمكنه تنزيل محاضرات أي من السنتين. تظهر المواد حسب إعدادات المواد الدراسية.
3. يستطيع المدرس رفع محاضرات PDF لمواده المسندة وحذف محاضراته، ويستطيع مشرف الدرجة الأولى إدارتها لجميع المواد.
4. الحد الأقصى لملف PDF هو 20 ميغابايت. يرفع المتصفح الملف مباشرة إلى مخزن Supabase الخاص عبر رابط رفع مؤقت، مع إظهار نسبة التقدم، ثم يحفظ الخادم بيانات المحاضرة بعد التحقق من اكتمال الملف. إذا لم يكن المخزن موجودًا، يحاول الخادم إنشاءه وإعداده تلقائيًا باستخدام مفتاح الخدمة.
5. إذا استمر ظهور خطأ الرفع، تحقق من `SUPABASE_SERVICE_ROLE_KEY` ومن الحد الأقصى العام لحجم الملفات في إعدادات Supabase Storage؛ الحد العام للمشروع له الأولوية على حد المخزن. تحفظ الملفات في مخزن خاص، ويُنشأ رابط تنزيل مؤقت بعد التحقق من حساب الطالب.
6. يرسل النظام إشعار تيليجرام عند إضافة المحاضرة إلى الطلاب الذين فعّلوا الإشعارات للسنة المعنية.

## إنشاء حسابات الطلاب

يستطيع مشرفو الدرجة الرابعة إنشاء حسابات الطلاب والبحث فيها ورفع طلبات تعديل للإدارة العليا. اضبط `SUPABASE_SERVICE_ROLE_KEY`، وتأكد من تشغيل `supabase-academic-management.sql` أولاً لتجهيز الفئات وسعاتها، ثم شغّل `supabase-audit-log.sql` و`supabase-degree-four-supervisor.sql` من محرر SQL في Supabase. يضيف الترحيل بيانات منشئ الحساب، مهلة الحذف والتعديل، التذاكر، كود تيليجرام الاختياري، وفرض تغيير كلمة المرور لطلاب السنة الأولى. كما يمنع الترحيل تكرار الرقم الجامعي حتى مع اختلاف الأصفار البادئة.

يقترح النموذج الرقم العددي التالي بعد أكبر رقم مستخدم، بحد أدنى أربعة أرقام. يعرض الفئات التي ما زالت فيها مقاعد متاحة للسنة المختارة فقط، ويتيح اختيار قسمي **تعويضات أسنان** أو **مساعد طبيب أسنان**، وخيار تسجيل موحد **عرب أجانب**. تحفظ أرقام الموبايل دون الأصفار في بدايتها. يمكن حذف الحساب الذي أنشأه المشرف خلال أول 24 ساعة وتعديله مباشرة خلال أول 48 ساعة؛ بعد ذلك يُرفع طلب التعديل للإدارة العليا ولا يُحفظ إلا بعد الموافقة. تُسجل عمليات البحث والتغييرات. تسجيل الحضور لمشرف الدرجة الرابعة متاح من الأحد إلى الخميس بين 08:00 و14:00 بتوقيت دمشق. يُطلب من طالب السنة الأولى تغيير كلمة المرور عند أول دخول.

إذا كان العمود `num` في جدول `students` لا يملك تسلسلاً تلقائيًا، شغّل أيضًا `supabase-student-account-num.sql` ليتم تعيينه تلقائيًا.

## إدارة السنوات والفئات والبرنامج

1. شغّل `supabase-academic-management.sql` بعد `supabase-teacher-portal.sql` في محرر SQL في Supabase.
2. استخدم حساب مشرف الدرجة الأولى، ثم افتح **إدارة المدرسين والمواد** لإضافة المدرسين، وإسناد المواد إلى المدرس والسنة الدراسية.
3. افتح **إدارة الفئات والبرنامج** لإضافة فئات مستقلة لكل سنة، وتحديد السعة ومواعيد البرنامج والفئة والمادة.
4. يجب أن تكون قيمة سنة الطالب قابلة للتعرّف كسنة أولى أو ثانية (مثل `أولى` أو `ثانية`). لا يُعرض جدول الدوام إلا عند وجود سنة واضحة، وتُحمّل الفئات والبرنامج بعد التحقق من دخول الطالب.
5. البرنامج القديم الذي لم يكن يحمل `student_year` سيبقى مخفيًا عن الطلاب. افتح كل موعد قديم في إدارة البرنامج، عيّن له المادة والمدرس والسنة والفئة الصحيحة ثم احفظه. أعد إنشاء الفئات القديمة من لوحة الإدارة مع اختيار سنتها؛ لا يمكن استنتاج سنة الفئات أو المواعيد القديمة تلقائيًا بأمان.

## سجلات النظام

1. اضبط `SUPABASE_SERVICE_ROLE_KEY` في بيئة الخادم، ثم شغّل `supabase-audit-log.sql` في محرر SQL في Supabase لإنشاء/تحديث جدول التدقيق ودعم أنواع الطلاب والمدرسين والمشرفين والدعم الفني (مشرفي الدرجة الرابعة).
2. تعرض صفحة **سجلات النظام** لمشرف الدرجة الأولى البحث بالاسم والرقم الجامعي وعنوان IP، والتصفية حسب نوع المستخدم ونوع العملية.
3. تشمل السجلات أحداث الدخول والخروج وتغييرات الحساب وكلمات المرور والفئات والحضور والإنذارات والإدارة الأكاديمية. لا تُسجل كلمات المرور نفسها.
4. يسجل الخادم عنوان IP الذي يمرره وكيل الاستضافة في ترويسات الطلب، إضافة إلى نوع الجهاز ومعلومات المتصفح والمنصة والوقت. قد لا يتوفر IP إذا لم يمرره الوكيل. قراءة السجلات محصورة بمشرف الدرجة الأولى.

## التشغيل محلياً

```bash
npm install
npm run dev
```

ثم افتح المتصفح على:

```bash
http://localhost:3000
```

## النشر على Vercel

1. ارفع المشروع إلى GitHub.
2. افتح Vercel.
3. اختر Import Project.
4. اختر المستودع الجديد.
5. الاحتفاظ بالإعدادات الافتراضية لـ Next.js.
6. اضغط Deploy.

## بناء الإنتاج

```bash
npm run build
```
